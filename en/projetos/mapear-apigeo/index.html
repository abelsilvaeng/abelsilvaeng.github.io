Projeto Mapear: APIGEO in production at PRF

The API that turns a field coordinate into a federal highway, kilometer marker, municipality and PRF unit, always on the current official network. In production at PRF, it serves the 13,758 locations of Projeto Mapear's 11th edition.

Problem

Since 2003, Projeto Mapear has identified the spots on federal highways where children and adolescents are vulnerable to sexual exploitation. For it to work, every field record has to become a highway, a kilometer marker, a municipality and a responsible unit, always according to the current official network.

Data and scale

  • Three official datasets versioned by release: SNV (DNIT), municipal boundaries (IBGE) and operational units.
  • Mapear's 11th edition (2025/2026): 13,758 vulnerable locations mapped on federal highways by PRF with Childhood Brasil, all placed on the official network by APIGEO.

Approach

  • FastAPI with PostGIS: lookup by coordinate and by state, highway and km, with linear referencing and km interpolation.
  • Updaters that detect, download, load, validate inside the database and activate each new release in a single transaction.
  • Quality gate in the database: a failed load never goes live and the current release stays in place.
  • Redis cache keyed by the versions of the three datasets, so a release switch never serves a stale answer.
  • Published through the WSO2 gateway and the corporate pipeline, with static analysis and security scanning.

How I validated it

  • Answers checked field by field against reference records.
  • My own validation, load and sizing protocol: OpenAPI contract against a baseline, functional ground truth, stepped load ramp with cold and warm cache, latency percentiles and Little's law to size connections.

Result

  • API in production at PRF, serving Projeto Mapear's 13,758 locations.
  • Automatic updates of the SNV, IBGE and operational unit datasets.
  • A validation and load protocol reusable for other APIs.

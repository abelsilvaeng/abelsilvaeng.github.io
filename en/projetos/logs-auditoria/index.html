Detecting automated use in audit logs

A pipeline that extracts hundreds of millions of audit records and a statistical layer whose heuristic rules flag usage patterns consistent with automation for human review.

1B+audit records processed and analyzed, 2023 to 2026

Problem

Internal Affairs needed to know when the use of corporate systems looked like automation rather than a person. The logs lived in Azure Data Explorer, and the per-query result size limit in that environment (about 64 MB) made a single-query analysis impossible: extraction had to be paginated and resume where it stopped after failures.

Data and scale

  • About 890 million audit and enforcement records from 2024 to 2026, over 280 GB.
  • With the 2023 series (about 338 million records), the analyzed base exceeds 1 billion records.
  • Sources: Azure Data Explorer and a remote relational database. Because this is a law enforcement agency, system, table and user names are not shown.

Approach

  • Incremental Python extractor: id-based pagination, on-disk checkpoints, retries and deduplication, so it resumes where it stopped without reprocessing.
  • Load into a MySQL instance tuned for the volume: indexes rebuilt after the load (3 to 5 times faster) and composite indexes aligned with the analytical queries.
  • Duplicate handling and event consolidation to avoid double counting. Operational keys and rules are not shown here.
  • Profiles per user and per month: rate per minute, dispersion, coefficient of variation and extreme percentiles, with window functions.
  • Heuristic regularity and burst rules on top of those profiles flag patterns consistent with automation for human review.

How I validated it

  • Interpolated percentiles computed in KQL and in MySQL, verified equal on the same input: switching engines did not change the number.
  • 29 months reprocessed end to end in about 5 hours, so the whole analysis can be rerun when a rule changes.

Result

  • The output prioritizes Internal Affairs' review: the most regular profiles and the most extreme bursts come first.
  • The profiles feed BI dashboards in production.
  • The pipeline is documented and can be rerun for new time windows.

My role

I designed and built the extractor, the MySQL database, the profiles and the rules, and documented each step. The BI dashboards consume this output.
